# V9 Immediate Entry and LTF-Noise Research Checkpoint

Date: `2026-09-13`
Status: `ACTIVE DECISION CHECKPOINT / ENTRY CONVENTION FIXED FOR REFINEMENT`
Base GitHub HEAD: `4707ac6993a9288afdbff6ae127074bbcd11d3a7`

## 1. Decision

The next V9 mechanical research phase will **not** search for a separate lower-timeframe entry trigger.

The entry convention is intentionally simplified:

```text
meaningful causal Arrival / Delivery event
-> immediate entry if the mechanical Grammar authorizes the Child
```

This removes a major optimization dimension before Hard-SL and journey research.

## 2. Why

Repeated V9 history showed that LTF trigger research creates many attractive but unstable degrees of freedom:

```text
micro BOS / CHOCH
FVG
OB
sweep
retest
displacement
candle pattern
retracement depth
N-bar confirmation
timing window
```

Some of these work in selected examples, but a stable reusable edge has repeatedly failed to survive broader review.

The current project therefore prefers to test whether the **Grammar itself** carries enough edge.

If immediate entry plus honest Hard SL and journey management cannot produce a robust strategy, an LTF trigger should not be used to hide that weakness.

## 3. Exact-clock correction

“Immediate entry” does not mean waiting for an H1 convenience boundary.

The intended final clock is:

```text
H4 liquidity exact first touch / raid at time T
-> information packet known at T
-> mechanical authorization
-> immediate executable entry
```

Historical H1-close / next-H1-open baselines remain useful comparators only.

M1/tick data remains necessary for:

- exact first-touch timestamp;
- executable-price evidence;
- spread / tick chronology when available;
- Hard-SL / TP ordering;
- intraminute ambiguity.

It is not currently authorized as an entry-pattern search space.

## 4. Research implication

Entry timing is no longer an optimization axis in the active phase.

The main mechanical degrees of freedom are now:

```text
Grammar authorization
Hard SL
TP / dynamic destination / journey management
multi-Child / exposure handling
```

This separation is deliberate.

If performance improves, the source of the improvement can be attributed more cleanly to risk boundary or winner harvesting rather than an overfit entry trigger.

## 5. AI deferral

Recent blind/pilot work did not justify AI as the current direction oracle or entry selector.

Therefore:

```text
AI improvement study = DEFERRED
```

until a strong mechanical policy has been established.

If AI is later tested, it must prove additive value over the frozen mechanical baseline rather than being used to create the baseline.

## 6. What is explicitly not frozen

This checkpoint does **not** freeze:

- final Hard-SL reference;
- final TP;
- final destination rollover policy;
- final repeated-Child / stacking policy;
- final live primary initialization;
- future-hidden permission;
- final spread/fill model.

It freezes only the research direction:

```text
NO ACTIVE LTF ENTRY-TRIGGER OPTIMIZATION
MECHANICAL EDGE FIRST
IMMEDIATE ENTRY AS BASE CONVENTION
AI LATER
```
